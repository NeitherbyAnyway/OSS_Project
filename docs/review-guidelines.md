# PR 리뷰 가이드

## 리뷰 의견 작성

변경된 코드나 문서의 구체적인 위치에 의견을 남기고, 문제와 영향 및 개선 방향을 설명합니다. 실제로 확인한 문제만 지적하고, 문제가 없다면 억지로 수정 의견을 만들지 않습니다.

- `[MUST]`: 병합 전에 해결해야 하는 기능 오류, 요구사항 누락, 데이터 손상 또는 안전성 문제
- `[SHOULD]`: 필수 수정은 아니지만 가독성, 유지보수성, 테스트 범위를 개선할 수 있는 제안

예시:

```text
[MUST] 이 입력이 비어 있으면 파싱이 실패합니다. 빈 입력을 처리하거나 사용자에게 유효성 오류를 반환해 주세요.

[SHOULD] 이 조건은 다른 처리 경로와 중복됩니다. 공통 함수로 분리하면 이후 변경을 한 곳에서 관리할 수 있습니다.
```

## 리뷰 제출

1. PR의 변경사항을 확인하고 필요한 경우 줄 단위 댓글을 작성합니다.
2. `Review changes`에서 `Comment`, `Approve`, `Request changes` 중 리뷰 결과에 맞는 항목을 선택합니다.
3. 보류 중인 댓글이 있다면 리뷰를 제출해 게시합니다.
